`misc.py` uses `np.bool` in `merge_sequences_given_tolerance`. That name was removed in

`numpy>=2,<3`.

### `wearable_minimal.py` (minimal rewrite, not a patched copy)

| | |
| --- | --- |
| Upstream path | `hypnospy/wearable.py` |
| Upstream sha256 | `74abb515fa7f8cc663d616c6a6fc9764d4fb3d0881ce5c0cdbffc56ea7635cc0` |
| Vendored sha256 | `4e100b202117dc6fae080317794cea6875647abc6ccb86ac09c146d5647f950f` |

The HR boundary algorithm reads only a small part of the upstream `Wearable`, and the upstream
class imports `h5py` plus the `RawProcessing`/`CGM` stack, so this is a **minimal rewrite**
(155 lines vs 307) rather than a patched copy. Three deliberate deviations, each neutralising a
defect class:

| # | Deviation | Why |
| --- | --- | --- |
| 1 | no frequency inference | upstream `get_frequency_in_secs()` falls back to `pd.infer_freq` (`wearable.py:98-115`) and raises on an irregular index; a wrong-but-set frequency silently rescales every window, because every window length is expressed in epochs. Here a missing frequency raises, so the adapter must call `set_frequency_in_secs`. |
| 2 | constructor signature | takes the frame directly instead of a HypnosPy HDF5 path / `RawProcessing` object. |
| 3 | `pd.Timedelta` instead of `pd.DateOffset` | both are an absolute whole-hour shift, but on a timezone-aware index pandas 3 re-localises the `DateOffset` result and raises `ValueError: Cannot infer dst time` at the ambiguous hour of a DST fall-back. |

The full unified diff (upstream -> vendored body) for all three files is in
`UPSTREAM_DIFF.json`; the `wearable_minimal.py` entry is recorded as a `rewrite` with its
deviation list, so an auditor can see the DST fix that the manifest's `status_reason` cites.

## 4. Upstream defects that survive vendoring (the adapter must neutralise each)

| # | Defect | Upstream site | Adapter mitigation |
| --- | --- | --- | --- |
| D1 | **NaN heart rate is labelled SLEEP.** `np.where((hr - threshold) > 0, 0, 1)`; `NaN > 0` is `False`, so `NaN` becomes `1` (sleep). A wear gap inside the search window becomes a sleep candidate. | `sleep_boundary_detector.py:48` | The adapter fills every invalid epoch (missing sample or gap >= 2 min) with a high sentinel (`gap_fill_bpm`) *before* the call, so a gap can never pass the threshold test, and re-applies the gap mask *after* the call. |
| D2 | **Threshold inheritance across days.** `resample('24h').quantile().dropna()` then `ffill/bfill` gives a day with no in-window HR a neighbouring day's threshold. | `:39`, `:45` | The adapter passes exactly one analysis-day block and withholds (`insufficient_coverage`) when that block has no finite in-window HR; `diagnostics.threshold_inherited_from_neighbour_day` is always reported. |
| D3 | **Frequency inference.** Every window length is expressed in epochs (`minutes * get_epochs_in_min()`), and upstream infers the frequency from the index. | `wearable.py:98-115` | The vendored `Wearable` has no inference path (it raises), and the adapter always calls `set_frequency_in_secs`. |
| D4 | **Fixed 24-hour analysis block at an integer hour.** No timezone and no wake-date concept. | `:39`, `:97`, `:144` | The adapter computes the FRWHOOP wake date and the IANA-local analysis block itself and hands the algorithm one block with `hour_start_experiment` = search-window start hour. |
| D5 | **Fixed default search window `(20, 12)`.** Excludes shift workers and naps. | `:63`, `:322` | The adapter always passes an explicit `search_window_local_hours`. |
| D6 | **Boundary refinement cannot extend across a gap, but the coarse pass already crossed it.** `hyp_sleep_vard` is `fillna(0)`, so a gap yields 0 and fails `> threshold`; the coarse pass has already labelled the gap as sleep (D1). | `:89-90`, `:113-133` | The sentinel fill (D1) breaks the coarse run at the gap, and the adapter reports `gap_fraction_inside_each_interval` and clips intervals at unresolved gaps. |
| D7 | **The threshold is relative, so a flat night is labelled entirely sleep.** The quantile of a constant in-window HR equals that constant, `(hr - threshold) > 0` is never true, and every epoch becomes a sleep candidate. | `:39-48` | The adapter reports `diagnostics.hr_dip_bpm` / `flat_night` and can withhold via `params.require_hr_dip_bpm`. |
| D8 | The class name is misspelled upstream (`SleepBoudaryDetector`) and `evaluate_sleep_boundaries` references an undefined `metrics` name. | `:10`, `:514` | Kept as-is (unused); the adapter only calls `detect_sleep_boundaries(strategy='hr')`. |
